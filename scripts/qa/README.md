# Проверки без длинных логов в чате

Из корня репозитория:

```powershell
python -X utf8 scripts/qa/run.py
```

Выполняет тесты мигратора по отдельным файлам, тесты запускателя и сборку переносимого пакета. Сервер не затрагивает. Печатает одну строку JSON: success, passed, failed, blocked, executed, reused и путь summary.json. Счётчики относятся к шагам, а не количеству unittest-тестов. Полные stdout/stderr каждого шага сохраняются отдельно, по умолчанию в исключённой из Git `private-vpn/qa/<дата-id>/`. Логи могут содержать секреты; не публиковать.

## Повторить только неуспешное

```powershell
python -X utf8 scripts/qa/run.py --failed-only "private-vpn/qa/<дата-id>/summary.json"
```

Повторяет failed/blocked; успешные шаги помечены как повторно использованные (`reused`). Это не новая проверка их работоспособности. При изменении плана или кода/шаблонов мигратора, QA или файлов команд reuse запрещён: запустите группу заново. Отпечаток не отслеживает изменение удалённого сервера, окружения, всех зависимостей и вложенных скриптов. Для нового серверного состояния всегда выполнять группу полностью.

При ошибке сначала читать summary.json, затем только нужный фрагмент указанного log. Не загружать все журналы и исторические отчёты в контекст. После исправления кода достаточно подходящей группы, но failed-only со старым отпечатком уже неприменим.

## Группы и приватные планы

```powershell
python -X utf8 scripts/qa/run.py --list
python -X utf8 scripts/qa/run.py --plan private-vpn/qa/plan.json --group server --list
python -X utf8 scripts/qa/run.py --plan private-vpn/qa/plan.json --group server --allow-server
```

Последняя команда подключается к серверу для шагов kind=server; шаги mutating останутся blocked. Для временных клиентов также требуется согласование: они создают контейнеры и трафик.

```powershell
python -X utf8 scripts/qa/run.py --plan private-vpn/qa/plan.json --group server --allow-server --approve proxy_traffic
python -X utf8 scripts/qa/run.py --plan private-vpn/qa/plan.json --group security --approve certificate
```

Эти команды приведены для выполнения после согласования конкретного этапа. Само наличие файла плана не является разрешением. Приватный план с адресами и audit-helper не публикуется; проверять его актуальность перед запуском на другом сервере. В публичном checkout приватного плана нет.

Формат плана: объект `steps`, массив шагов с `id`, `group`, `kind`, `command` (массив аргументов), `timeout` в секундах и необязательным `depends_on` (id предыдущих шагов той же группы). Подстановки: `{python}` — текущий Python, `{root}` — корень. Команды запускаются из корня без shell. План — доверенный исполняемый код, не загружать чужие планы вслепую. kind описывается автором плана, запускатель не доказывает отсутствие изменений в команде.

Виды: local — локальная команда; server — серверное чтение с `--allow-server`; mutating и publish — только с отдельным `--approve <id>`. Зависимый шаг блокируется, если предпосылка не прошла. При повторном запуске разрешения снова передаются явно. Вывод команды не появляется в итоговом JSON.

Таймаут прекращает локальное ожидание. Он не гарантирует остановку удалённого задания или всех дочерних процессов. После обрыва/таймаута серверного шага сначала проверить сервер, затем решать о повторе. Автоматического повтора серверных изменений нет.

## Публикация одной командой

Согласованная публикация общего кода и релиза (авторизация описана в ../release/README.md):

```powershell
python -X utf8 scripts/qa/run.py --plan scripts/qa/release.example.json --group release --approve publication
```

Сначала локальные проверки и сборка, затем публикация только после успеха. Git commit/push основного репозитория эта команда не выполняет. Публикация не является тестом установки на чистом VPS.

## Экономия контекста

Открывать `docs/agent-context.md`, для серверной задачи — приватную памятку, затем нужные строки кода и summary. Полную хронологию читать только при конкретной необходимости. Файлы исходников не минифицируются; прежние памятки сохранены приватно. Следующие результаты дописывать в отчёт, а памятку обновлять коротким актуальным состоянием, без накопления истории.
