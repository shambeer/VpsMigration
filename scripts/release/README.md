# Публикация общего кода и релиза

Из корня checkout VpsMigration или VpsSettings:

```powershell
python -X utf8 scripts/qa/run.py
python -X utf8 scripts/release/publish.py
python -X utf8 scripts/release/publish.py --publish
```

Без --publish проверяются локальные файлы и выводится список публикации; сетевых запросов нет. С --publish отправляются только явно разрешённые исходники, тесты, инструкции и файлы релиза. История исходного репозитория, private-vpn, конфиги пользователей и бэкапы не копируются. Посторонние файлы целевого репозитория блокируют синхронизацию вместо их удаления.

Авторизация: GH_TOKEN или GITHUB_TOKEN из окружения, иначе сохранённая Git Credential Manager авторизация GitHub. Токены не записывать в команды/план/исходники. Целевой репозиторий и хэш пакета берутся из dist/migration/release.json; текущий проект публикуется в shambeer/VpsMigration. Пароль SSH для публикации не нужен. Настройка видимости существующего репозитория не меняется.

Одна команда с проверками и сборкой перед публикацией:

```powershell
python -X utf8 scripts/qa/run.py --plan scripts/qa/release.example.json --group release --approve publication
```

Эта команда не выполняет git commit/push основного checkout. Неизменяемые опубликованные assets не заменяются. Обновление только документации/QA может оставить прежний тег бинарного пакета: исходники обновятся на main, старый релиз останется привязан к своей версии.

Перед публикацией проверить содержимое allowlist и diff. Проверка шаблонов секретов является дополнительной защитой и не заменяет просмотр. Новые публичные инструменты явно включать в public_sources; файлы из private-vpn не добавлять.
