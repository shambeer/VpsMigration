## Реализовано, но полного испытания ещё нет

- Чистая установка всего набора одним запуском мастера: компоненты проверены отдельно, полного CLI-прохода с нуля не было.
- Восстановление копии на другом чистом VPS с сохранением доступов.
- Российский relay: настройка двух VPS, их соединение и ограничения источников.
- Восстановление работы мастера после намеренного обрыва SSH/закрытия на каждом критичном этапе.
- Реальная очистка ненужных контейнеров/пакетов текущего тестового VPS: есть локальные проверки, разрушительный сценарий не выполнялся.
- Полный интерфейсный цикл обеих панелей, ручное обновление приложений их штатными средствами.
- Собственный загружаемый сайт, все SAN-домены и все расширенные комбинации XHTTP.
- Импорт актуальных профилей и routing-профилей в настоящие телефонные приложения, Wi-Fi/мобильные сети и поведение под фильтрацией.
- IPv6, UDP приложений через каждый протокол, длительная стабильность, максимальная скорость и 500 клиентов.

## Не реализовано или отменено

- Индивидуальный доступ каждому пользователю/устройству и его отдельный отзыв: сейчас personal/shared.
- Произвольный выбор каждого протокола при установке.
- Автоматическое создание всех узлов/инбаундов и управление всеми standalone VPN из 3DP.
- Автоматическая пересылка будущих произвольных портов панели.
- Покупка VPS/домена и настройка DNS у провайдера программой.
- Клонирование ОС и ядра, универсальное восстановление любых старых архивов.
- Шифрование резервного архива.
- Один импорт абсолютно всех протоколов в любое клиентское приложение: совместимые URI собраны в подписку, остальные доступны отдельными файлами/кнопками на общей странице.
- SQLite для 3DP: отменено владельцем, оставлен PostgreSQL.
- Универсальное автоматическое обновление major-версий приложений/БД: по решению владельца используются штатные механизмы приложений.

Ни одна из этих проверок не доказывает невозможность блокировки IP или протокола провайдером. Наблюдаемые сетевые результаты получены с серверных контейнерных клиентов, а не из всех пользовательских сетей.

## Как раздавать доступы

Актуальные секретные файлы находятся в локальной приватной папке `private-vpn/server-settings/research/fr-audit-20261128/access/`. Их не нужно публиковать в GitHub. Сам код установщика доступен публично, доступы — отдельно.

1. Себе передавать содержимое роли **personal**, остальным — **shared**. Внутри каждой роли: `configurations/` — конфигурации, `strings/` — строки подключения, `subscriptions/` — состав подписки и routing-профили, `delivery/` — готовая страница/manifest/ZIP. Административный каталог `admin/` никому из пользователей не выдавать.
2. Самый удобный способ — отправить человеку его HTTPS-ссылку страницы доступа из `delivery/start.txt` (там записаны страница доступа и подписка). Страница содержит подписку и отдельные файлы. Нельзя отправлять ссылку другой роли: владелец ссылки получает все доступы этой роли.
3. Для совместимого XRay-клиента можно отправить только строку HTTPS-подписки из `strings/subscription.txt`. В приложении добавить её как подписку и обновить. Подписка включает совместимые VLESS/Hysteria2/Shadowsocks URI; поддержка каждого транспорта зависит от приложения. Универсальный импорт во все приложения не подтверждён.
4. AmneziaWG и обычный WireGuard выдавать отдельными `.conf` из `configurations/`, импортировать в приложение с поддержкой соответствующего протокола. Обычный WireGuard-клиент не обязательно поддерживает AmneziaWG. OpenVPN выдавать отдельным `.ovpn`; Telegram — его `tg://`/`https://t.me/proxy` строкой из `strings/`.
5. Для ручного добавления совместимого протокола отправить его отдельную строку из `strings/` либо конфиг из `configurations/`. Не путать клиентский JSON XRay с форматом импорта конкретного мобильного приложения.
6. ZIP из `delivery/` отдаёт весь клиентский комплект одной роли. Он содержит секреты; передавать лично, не размещать в открытом канале. Резервные архивы сервера и SSH-ключи пользователям не раздавать.

Сейчас shared — один общий комплект, а не отдельная учётная запись каждого человека. Отозвать одного получателя без смены общих доступов остальных нельзя. Для WG/AWG одинаковый профиль на нескольких одновременно работающих устройствах может приводить к переключению endpoint и обрывам; лучше отдельный peer на устройство. Автоматическое создание индивидуальных peers/пользователей мигратором ещё не реализовано.

После обновления подписки у получателя следует проверить подключение и открытие сайта в его сети. Серверные испытания не гарантируют работу в каждой сети пользователя.


## Дополнительные реальные проверки

- Повторная проверка существующего полного архива: внешний SHA256, девять внутренних SHA256 и безопасные пути членов архива совпали. Это не восстановление.
- Certbot renew --dry-run с существующей конфигурацией сертификата: успешно. Первый запуск остановлен в случайной задержке Certbot, повторный выполнен с --no-random-sleep-on-renew. Рабочий сертификат не заменялся.
- HTTPS-защита: девять сценариев прошли. Неверные токены дали404; .env и скрытый каталог выдачи —403; попытка обхода родительских путей —404; POST подписки —403, POST страницы —405; подмена роли/URL параметрами запроса не изменила содержимое personal/shared.
- Обычная выдача подписок, страницы, manifest и ZIP одновременно успешно сверена. Проверка не доказывает отсутствие всех возможных уязвимостей и не запрещает владельцу shared переслать свой общий доступ другому человеку.


### Свежая копия после исправления WARP

По отдельному разрешению выполнен новый согласованный снимок с временной остановкой служб. Архив скачан локально, внешний SHA256 и девять внутренних SHA256 проверены; отдельно сохранены и проверены настройки SSH, Fail2ban, UFW и fstab. Размер основного архива — 618 370 137 байт. Конкретные приватные пути и контрольные суммы сохранены в закрытом отчёте.

После копирования подтверждены: все15контейнеров работают без OOM, SSH/Docker/Fail2ban активны, API3DP отвечает, AmneziaXRay и оба WARP-варианта работают для personal/shared, подписки/страница/manifest/ZIP совпадают с экспортом. Новый архив не является образом ОС; его восстановление на другой VPS ещё не испытывалось.
