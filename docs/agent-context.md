# Контекст проекта

## Загружать только нужное

1. `git status --short` и этот файл.
2. Для сервера — `<private-root>/server-settings/agent-context.md`, если существует. Локальный `.private-root` задаёт отдельный каталог секретов; без него используется private-vpn/. Без задачи о сервере его не читать.
3. Карта требований: [functional-requirements.md](functional-requirements.md); читать только нужные FR.
4. Проверенные возможности и раздача: [итоговый отчёт](reports/verified-status-20261128.md). Старую хронологию по умолчанию не читать.

## Код и запуск

- `scripts/migration/vps_migration/`: `cli/` — мастер/resume, `core/` — общие функции, `server/` — VPN/relay/backup/maintenance, `packaging/` — пакет и запускатели.
- `migrate.py`, `remote.py`, `build_portable.py` — точки входа внутри scripts/migration/.
- Инструкция продукта: `scripts/migration/README.md`. Публичный пакет: shambeer/VpsMigration; единственный источник общего кода: этот checkout VpsMigration.
- Новые серверные модули включать в фиксированный SERVER_FILES в `packaging/portable.py`.

## Экономная проверка

- `python -X utf8 scripts/qa/run.py` — локальные тесты по файлам и сборка; одна строка JSON, логи в ignored `private-vpn/qa/`.
- `--failed-only <summary.json>` — повтор неуспешных/заблокированных шагов при неизменном плане и коде. После изменений нужен полный запуск нужной группы.
- Серверные/публикационные планы и разрешения: `scripts/qa/README.md`. Читать summary и только относящийся к ошибке фрагмент лога.
- Не запускать серверные проверки или публикацию ради обновления отчёта. Согласовывать изменения сервера; не выдавать локальные тесты за Linux/телефонные.

## Правила

Русский язык; короткий чат, подробности в файлах репозитория. Не добавлять комментарии в код. Адреса, домены, ключи, доступы, журналы и архивы — только private-vpn/. Не печатать секреты. Не менять сервер без согласования, не запускать полный установщик поверх рабочего набора. Публикация только по поручению; использовать scripts/release/publish.py.

Прежняя хронология памяток сохранена приватно в docs/context-history/ внутри server-settings; читать только для конкретного вопроса.

Публичный набор расширен: scripts/qa/, scripts/release/, требования/порты/несекретные отчёты. Издатель синхронизирует явный allowlist; его прежняя приватная точка входа — совместимая обёртка. План публикации: scripts/qa/release.example.json.

Общий код перенесён из VpsSettings; старый checkout используется только для приватных материалов. Не восстанавливать в нём вторую копию исходников. Скрипты публикации теперь в scripts/release/.
